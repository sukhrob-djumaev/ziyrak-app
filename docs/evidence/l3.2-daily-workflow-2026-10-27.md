# L3.2 useful, honest daily workflow — implementation record (2026-10-27)

PR #53 (`feat/l3-2-daily-workflow`); verified head `2473fbf`. Covers D09 (F13, F14), D11 and the shell/keyboard/mobile/empty-state items of the L3.2 row in `docs/launch-roadmap-2026-10-25.md`.

## Changes
- **Navigation by work:** Support / Teach the assistant / Set up / Insights / Workspace (`src/lib/navigation/dashboard-nav.ts`); same `requires` permission per item. Labelled `nav`, `aria-current` on the open page, skip link to `#main-content`, one `h1` per page, focus rings, named icon-only controls.
- **Phone width:** sidebar hidden below `md`; a menu bar on every dashboard page opens a modal drawer (Tab trapped, Escape closes, focus returns to the button, closes on navigation). Knowledge page stacks its two panels.
- **F13:** `src/lib/analytics/response-time.ts` measures first `customer` (or legacy `user`) message to first `assistant`/`agent` reply and returns its sample size; the page shows "No replies yet" instead of 0.
- **F14:** Keyword Alert cannot be created (UI, `POST`) or chosen (`PUT` type); existing rules stay visible, can be switched off/deleted, say they send nothing. Wiki marked not available.
- **D11:** served OpenAPI no longer names the upstream project/licence, lists only the supported channel values (`whatsapp_cloud`, `webchat`), documents cookie and `x-api-key` auth, and says it is not exhaustive. In-app API docs corrected.
- **Visible failures:** Customers, Tickets, Knowledge, Canned responses, SLA, Automation, Business hours use `submitJson` + `useReportWrite` (refused save → error toast, form stays open); lists use `LoadFailed` (never shown as empty). Business hours never shows defaults after a failed load (a save would overwrite the real schedule). Analytics (with stale-response guard) and Activity show a load failure. Toasts are an `aria-live` region.
