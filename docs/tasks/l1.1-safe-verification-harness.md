## Required cases and implementation sequence

- Missing URL, only one DB variable, contradictory URLs, inherited DIRECT pointing elsewhere, invalid protocol, protected live/acceptance target and insufficient run ownership: reject before any side effect. A name ending `_test` alone is not proof of ownership. A pooled/direct pair must have an explicit validated relationship, not simply be accepted because both are nonempty.
- Explicit disposable ordinary test target and independently named load target: allow only the intended operations. Ensure environment loading cannot restore a stale production URL after validation. No secret/password/complete connection URL in diagnostics.
- Process cleanup: missing ownership, changed PID birth/cwd, reused PID, wrong run and unrelated process: no signal; valid owned identity: bounded cleanup of that process only. No `pkill`/`killall` or name-based matching.
- Build/container cleanup: stale existing image cannot silently satisfy the run; record build/source identity and use the identified image. Teardown must be limited to this run's owned project/resources, never a shared or live stack. Resource deletion retains applicable owner authorization.
- CI and the signup-seeded suite must deliberately provide accepted disposable targets. Guard tests must run without a real DB so incorrect configuration is caught before test setup can connect.
