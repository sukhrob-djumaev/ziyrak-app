## What changed since the holdout7 gate and why
holdout8-17 were each run once and then consumed; each failure led to one change in what the model sees, never to reply text:
- hand-off honesty: unknown questions are handed off automatically; tool-failure results say "FAILED and NOT carried out", name the failed action in later results, and a final-position reminder repeats it; the reply must open by saying what they asked for did not go through.
- no invented denials: a rule forbids "we cannot / do not" unless the knowledge base says so, and forbids answering an offer question by sending the customer elsewhere.
- safety lines in the knowledge base must be stated; scorer checks added for unbacked promises, undisclosed failures, missing safety.
- holdout16 diagnosis: the failed-tool misses were a scorer proxy fault (any tool counted, so a ticket hid that the email was never tried). Now only the tool under test counts, the tools that ran are recorded per turn, and the model is told to use the tool the customer asks for as well as any ticket.
- holdout17 (7/8, valid): its only miss was five correct safety replies flagged by an over-broad bare "safe" pattern (case-design fault). No code change; holdout18 uses patterns that need an affirmative answer.

## Limits - what this does not prove

- 45 cases, 5 small-business domains, English, one provider/model. Three of the eight prior sets were failed gates; this is the first pass after the diagnosis, on a fresh set.
