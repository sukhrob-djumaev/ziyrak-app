# L4.1a capability registry and versioned catalog — implementation record (2026-10-28)

PR #54 merged as `a977869`; verified head `b7b1e2b`. Design: `docs/l4.1-catalog-entitlements-design.md` (Revision 2, after an independent design review). Provider-neutral; no money is collected.

## Delivered
- Code-owned registry of five boolean capabilities the product already implements (`src/lib/billing/capabilities.ts`); no Email, Phone, Keyword Alert.
- `CatalogItem` / `CatalogVersion` (additive migration `20261027000000_l4_1a_catalog`): draft → published (immutable) → archived. Database enforces: lifecycle vocabulary and sellable-shape CHECKs, published/archived immutability (only published→archived changing state/archivedAt/updatedAt, archived final, draft cannot be archived), no delete/truncate of history, permanent item key/kind, one open draft per item.
- Service (`src/lib/billing/catalog.ts`): create item, save draft (rev compare-and-set), new draft from latest published, publish (pure `publishProblems` validation: implemented capabilities only, amounts only on limits, no duplicates, complete price, known ISO currency), archive; one mandatory audit row per action in the same transaction.
- Super-admin-only `/api/platform/catalog` and `/platform/catalog` console (same gate pattern as the AI service console); publish/archive/new version require a typed reason.
