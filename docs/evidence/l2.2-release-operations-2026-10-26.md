## Pipeline
- `scripts/release/image-smoke.sh <image> <sha>`: tests the image itself under the STRICT production contract with a real Postgres: contents (no src/tsx/test tools/npm/Chromium; prisma CLI present), worker refuses an incomplete configuration, web migrates and becomes live and ready, worker heartbeat `ok` via the token-protected health summary, build SHA equals the commit, public health leaks no detail, worker stops with exit 0 on SIGTERM.
- `scripts/release/image-scan.sh`: Trivy, fixable HIGH/CRITICAL fail the job.
- CI: new `image` job after `build`. `docker-publish.yml`: requires a successful CI run for the exact commit, then builds once, smoke-tests, scans, and pushes THAT image, printing the digest. It runs only on a published release or by hand; nothing was published during this work.
- Bugs found only by running the real image and fixed: native ESM cannot resolve `next/server` (CJS bundle instead); the generated Prisma client needs `import.meta.url` (defined at bundle time); the worker's import-time `JWT_SECRET` check fired before the configuration contract (contract now imported first); a recursive `chown -R /app` duplicated the whole app layer (ownership at COPY time).
- Load-test fixes: the Web Chat stream check predated the visitorId requirement; the web process now opens the Redis connection at startup (a cold connection overran the 250 ms budget and silently produced per-process rate limits).

## Operations
- `tests/unit/migration-compat.test.ts`: expand/contract rollback guard over all 29 migrations (two early Phase 1 contract migrations grandfathered; new breaking ones need a justified marker).
- `scripts/ops/restore-drill.sh`: first drill on the isolated test database: 132 tables, 0 row-count mismatches, dump+restore 9 s, restored migration count equals the checkout (29). Proves the procedure, not production restore time.
- `docs/guides/operations-runbook.md`: release identity, rollback, restore, retention (and the missing whole-workspace offboarding), alert signals, incident ownership, capacity.

## Verification
- Image: build OK, smoke test OK, scan 0 fixable HIGH/CRITICAL (local Docker, 2026-10-26).
- Multi-replica load test (`scripts/loadtest/run.sh redis`, isolated Compose project, 2 web + 2 worker replicas + PgBouncer + Redis, stand-in AI 300 ms): **9/9 checks PASS** on the final image: shared rate limit 5 allowed / 25 limited, 48/48 jobs exactly once with 0 ordering violations, jobs shared 8/40 across workers, realtime delivered across replicas, scale-down 24/24. Before the fixes above the same test failed 2 checks (stale check, cold Redis).
- Not measured: production capacity. A laptop with a stand-in AI is not the intended topology; no throughput numbers are claimed.

## Open / limitations
- Registry push, release tagging and deployment were not performed (need owner authorization). The publish workflow is untested end to end (no release was cut); its steps are the ones exercised locally.
- RPO/RTO, backup mechanism, alert routing and incident owners are owner inputs (marked in the runbook). Whole-workspace offboarding is not implemented.
- `apt-get upgrade` and the unpinned `node:22-slim` base make the image content depend on build time; the digest, not the tag, is the identity.
