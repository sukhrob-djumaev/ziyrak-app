# L2.1 runtime and configuration contract — implementation record (2026-10-26)

Status: implemented on `fix/l2-1-runtime-contract`; CI and combined-build browser run pending at time of writing.

## Changes
- F04 probes: `/api/health/live` (no dependency), `/api/health/ready` (503 while the database is down; Redis/provider never gate it), `/api/health` summary follows readiness (previously 200 on database failure; the old OpenAI check read the legacy Settings table and is gone). Public answer = status + dependency states only; build identity, worker/queue facts, memory need `HEALTH_DETAIL_TOKEN` + `x-health-token`.
- F11: `WorkerHeartbeat` table + heartbeat file written after each successful database write; worker state ok/stale/none and instance count in the summary; queue oldest-waiting age, failures in the last hour and active count from pg-boss tables (SQL verified against a real pg-boss schema); deployed build identity via `APP_BUILD_SHA` image build arg. Compose worker now has its own file-based healthcheck (it used to inherit the web HTTP probe).
- F05: `src/lib/config/runtime-contract.ts` validated at web startup (instrumentation) and worker start; strict in production, only `ZIYRAK_CONFIG_PROFILE=relaxed` exempts (local Compose, acceptance runtime, load test); `npm run config:check`. Helm: complete Secret/ConfigMap keys (encryption keys by version, platform proofs, SMTP, MFA mode, health token), refuses defaults/incomplete values, in-chart PgBouncer now works with `secrets.existingSecret`, liveness/readiness/startup and worker heartbeat probes. Migration `20261026030000_l2_1_worker_heartbeat`.
- `TRUSTED_PROXY_HOPS` (>= 1) is now a startup requirement in production (previously only a log line).

## Verification
- Unit/API: `tests/api/health.test.ts` (liveness independent of DB, readiness 503/recovery, no outbound call, detail only with token), `tests/unit/runtime-contract.test.ts` (10+), `tests/unit/startup-failure.test.ts` (real worker entrypoint exits non-zero listing problems, no secret values), `tests/repository/worker-heartbeat.test.ts` (real Postgres), `tests/unit/helm-chart.test.ts` (real `helm template`, Helm 3.16.2 via Docker locally; skipped where no helm).
- Real-process dependency outage/recovery against a running stack and a live Redis outage drill: see browser/acceptance section when run.

## Independent review (Opus, read-only): nothing critical/high
Fixed: worker exec probe timeout (1 s default could restart a throttled healthy worker -> 10 s); web startup probe no longer depends on the database; Compose no longer hard-forces the relaxed profile (`ZIYRAK_CONFIG_PROFILE` is overridable, default relaxed for the local stack); unauthenticated health probes share and cache results (`HEALTH_CACHE_MS`, default 1.5 s) so a flood is not a flood of queries; `MAIL_TRANSPORT` other than unset/`smtp` is an error; dead workers' heartbeat rows are pruned; chart rejects non-production `config.nodeEnv`, bad encryption key names/lengths and a missing mail sender (mail check waived with `existingSecret`); the chart test fails (not skips) in CI when helm is missing; comments no longer claim the heartbeat proves job throughput.
Not changed: heartbeat timestamps use the worker's clock (NTP skew is far below the 60 s threshold); the public summary still names which dependency is down (status + dependency states only).

## Limitations / open
- Probe contract is verified in-process and by chart rendering; no cluster was available, so kubelet behaviour was not exercised.
- The deployed image identity is reported, but the image is still built per environment (F12: immutable build-once-promote is the next task).
- Worker heartbeat file path defaults to the OS temp dir inside the container; a read-only root filesystem needs `WORKER_HEARTBEAT_FILE` on a writable mount.
- Queue alarms are exposed, not wired to an alerting system (that is an operations setup item).
