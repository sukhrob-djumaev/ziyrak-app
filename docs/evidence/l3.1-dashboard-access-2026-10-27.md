# L3.1 dashboard and access coherence - implementation record (2026-10-27)

Merged as PR #52 (`786e89b`); verified head `4c22555`. Covers D01-D08 and D10 of `docs/dashboard-and-access-review-2026-10-25.md`. D09 (analytics metric, Keyword Alert) and D11 (served OpenAPI) belong to L3.2.

## What changed
- D01: navigation and write controls come from a server-derived permission list (`src/lib/rbac/view.ts`, `src/lib/navigation/dashboard-nav.ts`, `PermissionsProvider`). Members limited to specific channels also lose Webhooks and Automation (their APIs require workspace-wide authority). `RouteGuard` shows "Access denied" for a restricted path and never mounts the page. API checks are unchanged and remain authoritative.
- D02/D03: "My account" page separate from Workspace settings; inert search and bell removed.
- D04: "Team roster" (assignment, not login accounts) vs "People & Access" (login accounts).
- D05: `submitJson` helper; Team and Webhooks forms stay open on failure with a reason and keep entered values; 401/403 use written copy.
- D06/D07: legacy BYOK checklist removed; setup panel owner-aware, load failure visible, links gated by permission.
- D08: Channels shows supported vs "not verified for this release" (Email/Phone); read-only for roles without `channels:update`.
- D10: J13 sets the approval policy and approves/rejects through the Approvals UI (row selected by action id; policy reset also on failure). Viewer denial stays at API level.
- New journey J31 (five roles): navigation vs an independent contract table, direct URLs (denial, no protected requests), write controls, account menu, rejected-write behavior.

## Open / limitations
- The permission list is computed per full page load; an open tab keeps showing controls after a role change until reload (API still denies). Optional: refresh on 401/403.
- Pre-existing, separate ticket: `GET /api/webhooks` returns stored custom headers to supervisors holding only `webhooks:read`.
- Workspaces without an `OnboardingState` row get no setup guidance now that the checklist is gone.
- Customers pages for scope-limited members (`customerProfileAccess`) are not hidden by the permission view.
- No observed task-based sessions with intended users yet (L3.2).

## Run-environment lessons (not product defects)
- Browser runs stalled for ~15 min per journey on battery (maintenance sleep) and under heavy external CPU load; a control run of the already-merged L2.2 build stalled identically. Valid runs need AC power and a calm machine.
- The task Redis keeps hourly invitation rate-limit counters across runs; flush it (`redis-cli FLUSHALL` on the task-owned container) before each full run, or j28 fails with "Too many invitations".
- A fresh acceptance DB needs `prisma migrate deploy` before `start-all.sh`.
